# BepInEx のファイルの確認（SHA-256）と、その値の変え方

StarPocket Client は、インストールのときに BepInEx を配布元からダウンロードします。
その中身はゲームのフォルダーに展開され、ゲームの中でプログラムとして動きます。
ですから「どこから来たファイルか」だけでなく「そのファイル自体が本物か」も確かめます。

この文書は、**BepInEx の新しいビルドに乗りかえるときに、オーナーが何をすればよいか**を書いたものです。

> **確かめているのは BepInEx の zip だけです。**
> PocketRoles 本体（MOD）の zip は、中に `PocketRoles.dll` が入っているかを見るだけで、
> SHA-256 は確かめていません（配っているリリースに、突き合わせる値をまだ置いていないためです）。
> その DLL も、BepInEx のファイルと同じようにゲームの中でプログラムとして動きます。
> 「ファイル自体を確かめている」は、今は **BepInEx の zip についてだけ**の話です。
> リリースに `SHA256SUMS.txt` を一緒に置けば、MOD の zip も同じ仕組みで確かめられます（これからの作業）。

---

## 1. 今どうなっているか

確かめることは 2 つあります。

| 確かめること | どこに書いてあるか |
|---|---|
| **どこから取るか**（https で、次の 4 つのホストだけ。`api.github.com`・`github.com`・`objects.githubusercontent.com`・`builds.bepinex.dev`） | `src\Core\Downloads.cs` の `WebFetch.AllowedHosts` |
| **何が来たか**（ファイルの SHA-256 が、書き留めてある値と同じか） | `src\AppInfo.cs` の `BepZipSha256` と `BepSha256()` |

今、書き留めてある値はこれです。

| 項目 | 値 |
|---|---|
| BepInEx の版 | `6.0.0-be.735` |
| 種類 | **win-x64（64 ビット）** — 2026.9.29（v19.0.0）から Among Us 本体が 64 ビットになったためです |
| ファイル名（配布元） | `BepInEx-Unity.IL2CPP-win-x64-6.0.0-be.735+5fef357.zip` |
| ファイル名（`%TEMP%` に置くとき） | `BepInEx-Unity.IL2CPP-win-x64-6.0.0-be.735.zip`（`AppInfo.BepZipName`。`+5fef357` は付けません） |
| 取ってきた場所 | `https://builds.bepinex.dev/projects/bepinex_be/735/` |
| 大きさ | 34,202,062 バイト（約 34 MB） |
| SHA-256 | `badef8112853a00939a0df6ca143bc0a4e3dc02bd4d21b873302731bfa0e4df4` |
| 確かめた日 | 2026-10-01 |

> **記録（2026.8.18 まではこれでした）**
> 2026.8.18 までの Among Us は 32 ビットだったので、入れていたのは **win-x86** の方でした。
> ファイル名 `BepInEx-Unity.IL2CPP-win-x86-6.0.0-be.735+5fef357.zip` ／ 31,305,993 バイト ／
> SHA-256 `9cd83eae4d47ab07e4ad7f4d98a0085f60fb4b61957857ff197c8729cf1bc483` ／ 確かめた日 2026-09-23。
> そのときは手元の控えとも突き合わせました（PowerShell 版ランチャーが 2026-09-08 に配布元から取ってきて
> `%TEMP%\PocketRolesLauncher\` に残っていた同じ zip（31,305,993 バイト）の SHA-256 が、1 文字も違いませんでした）。
> **この値はもう使いません。**版の番号は同じ `6.0.0-be.735` なので、`BepZipSha256` の表には
> 同じ鍵に 2 つの値は置けません。今このアプリが入れるのは x64 の方だけです。

### いつ確かめるか

1. ダウンロードが終わった**直後**。まだ何も展開していない時点です。
2. `%TEMP%` に前のファイルが残っていた場合も、使う前に同じように確かめます
   （このフォルダーは今までの PowerShell 版ランチャーと共用なので、誰が置いたファイルか分かりません）。

### 合わなかったときどうなるか

- そのファイルを**消します**。
- **展開しません**。ゲームのフォルダーには何も入りません。
- 画面と `client.log` に、日本語・中文・English で次のように出ます。

  > ダウンロードしたファイルが、配布元の本来のものと違いました。安全のため、そのファイルは消しました。ゲームには何も入れていません。通信が途中で切れた時にも起こります。もう一度お試しください

- 記録用に、本来の値と届いたファイルの値の 2 つも `client.log` に残します。
- 取得先の住所が 2 つ書いてあるので、1 つ目で合わなければ 2 つ目も試します。どちらも合わなければインストールのその手順は失敗になります（ほかの手順はやり直せます）。

### 値が書いていない版だったら

**入れません。**「確認できないけれど、とりあえず入れる」という逃げ道はわざと作っていません。

> この BepInEx (◯◯) の正しいファイルの記録が、このアプリにありません。安全のため、ダウンロードも展開もしません。アプリの更新をお待ちください。

と出して止まります。ネットにもつなぎません。

さらに、**アプリが入れようとしている版の値が書いていないと、ビルドが赤くなります**。
自己テスト（`src\SelfTest\InstallSelfTests.cs` の「BepInEx: the file itself」）が
「`AppInfo.BepInExVersion` の値が `BepZipSha256` にあるか」を毎回確かめているからです。
版の番号だけ上げて値を書き忘れる、ということは起こりません。

## 2. 新しい BepInEx に乗りかえるときの手順

ゲームが新しくなって、新しい BepInEx が要る、というときの手順です。
**1 回だけダウンロードが必要**です。値は推測できませんし、してはいけません。

### 手順

1. **新しいビルドを決める。**
   `https://builds.bepinex.dev/projects/bepinex_be` を開きます。
   要るのは **`BepInEx-Unity.IL2CPP-win-x64-…`** です。ここを間違えないでください。
   - `Unity.IL2CPP` … Among Us は IL2CPP です（`Unity.Mono` ではありません）
   - `win` … Windows です
   - `x64` … **2026.9.29（v19.0.0）から Steam 版の Among Us は 64 ビットです**（`x86` ではありません）。
     2026.8.18 までは 32 ビットだったので `x86` を入れていました。ここが今いちばん間違えやすい所です。
     不安なときは、**3 章「ゲームの種類（32bit / 64bit）が変わったとき」**の確かめ方を先に読んでください。

2. **そのファイルを 1 回だけダウンロードする。**
   ゲームのフォルダーには入れないでください。どこか作業用のフォルダーで結構です。

3. **SHA-256 を読む。** PowerShell で次のように打ちます。

   ```powershell
   Get-FileHash -Algorithm SHA256 "<ダウンロードしたファイル>" | Format-List
   (Get-Item "<ダウンロードしたファイル>").Length
   ```

   出てきた 64 文字が値です。大文字で出るので、**小文字に直して**書き留めます。

4. **配布元が値を公開していないか見る。**
   もし公開されていて、自分で計算した値と**違ったら、そこで止めてください**。
   自分の値を書き込んではいけません。まずどちらが正しいのかを調べます。
   - 2026-09-23 現在、`builds.bepinex.dev` は zip の SHA-256 を公開していません。
     ページに出ている短い英数字は、そのビルドの**元になったソースの印**であって、zip の値ではありません。
   - ですから今の値は「その日に公式の配布元が配っていたファイル」を書き留めたものです。

5. **`src\AppInfo.cs` を直す。** 次の 4 か所です（ここ以外に版の番号と種類を書いた場所はありません。
   一覧ページから探すときの検索の文字列（`src\Core\Installer.cs` の `BepHref`）は
   **`AppInfo.BepZipName` のファイル名そのもの**から組み立てているので、手で直す必要はありません。
   版だけでなく**種類（x86 / x64）も一緒に付いてきます。**
   自己テスト「the spare way in follows the pinned version」が、版が合っていて種類だけ違うリンクを
   拾わないことも含めて毎回確かめます）。

   ```
   BepInExVersion   … 版の番号（例 "6.0.0-be.800"）
   BepZipName       … %TEMP% に置くときのファイル名（ここに win-x64 / win-x86 の別が入ります）
   BepUrls          … 取りに行く住所 2 つ（%2B の形と + の形）
   BepZipSha256     … 版 → SHA-256 の表。新しい行を足す
   ```

   `BepZipSha256` の行には、必ずコメントで**ファイル名・バイト数・取ってきた場所・確かめた日**を書きます。
   種類を替えたときは、**なぜ替えたか**（ゲームが何ビットになったか）もそこに書きます。

6. **古い行は消さない。**
   古い版の行を残しておくと、古いアプリと同じ `%TEMP%` を使ったときにも中身が確かめられます。

7. **ビルドしてテストする。**

   ```
   dotnet build StarpocketClient.csproj -c Release
   "bin\Release\StarPocket Client.exe" --self-test <作業用フォルダー>
   ```

   `RESULT PASS` になれば大丈夫です。値の書き方（64 文字・小文字）が違えば、ここで赤くなります。

8. **ダウンロードしたファイルを消す。** 用は済みました。

9. **実機で 1 回だけ確かめる。**（**この手順が終わるまで公開しないでください**）

   自己テストが使っているのは、自分で作った小さな偽の zip だけです。
   **「今日の本物の配布元が、書き留めてある値と同じバイトを返すか」**と
   **「その本物の 34 MB を実コードで展開できるか」**は、そこには入っていません。
   値が 1 文字でも違うと、配ったあと全員のインストールが [3/5] で止まり、
   画面には通信の失敗のように見える文しか出ません（原因は `client.log` の「ファイルの照合:」の行にしか出ません）。

   それを確かめるためのコマンドがあります。

   ```
   "bin\Release\StarPocket Client.exe" --verify-download
   ```

   配布元からファイルを 1 つ受け取り、値と中身を確かめ、作業用のフォルダーに展開して、**全部消します**。
   終わると日本語 1 文の小さい窓が出ます。読むのはその 1 文だけです。

   - **ゲームのフォルダーには触れません。** フォルダーの場所（`Paths.Modded`）を参照しない経路です。
     `Installer.Expand` も呼ばないので、`.starpocket-unpacking` の印もどこにもできません。
   - 作業用は `%TEMP%\StarPocket-verify` だけです（**PowerShell 版と共用の `%TEMP%\PocketRolesLauncher` は使いません**）。
     一時的に約 150 MB 使い、終わったら 0 になります。
   - **確かめる処理そのもの**（`src\Core\BepVerifier.cs`）は `launcher-state.json`・Steam・レジストリ・
     ショートカット・`ClientContext.CacheDir` のどれにも触れません。ゲームの記録は 1 バイトも変わりません。
   - ただし**コマンド全体としては副作用がゼロではありません**。この分岐は `ClientContext.Detect` のあとに
     置いてあるので（`src\Program.cs`。`--action` / `--scan-only` と同じ場所）、アプリ自身の
     `%LOCALAPPDATA%\StarPocket\Client` には `client.log` が 1 回増え、**その場所に
     `launcher-state.json` がまだ無ければ 1 度だけ作られます**（古いランチャーの内容の引き継ぎ。
     `ClientContext.LoadState` → `LauncherStateFile.MigrateFrom`）。Steam を探すためにレジストリも読みます。
     ゲームのフォルダーと、遊ぶための記録の中身は変わりません。
   - Client が開いていても、ゲームが起動中でも走ります。
     ただし**このコマンドを 2 つ同時に走らせることはできません。**先に動いている方が作業用フォルダーを
     持っているので、あとから始めた方は「もう 1 つ確認が動いています」と出して何もせずに終わります
     （終了コード 1）。先に動いている方には一切手を触れません。
   - 自動で走らせるときは `--quiet` を付けます（窓が出ず、コンソールと `client.log` だけ）。
     **起動そのものに失敗したときも窓は出ません**（`Program.StartFailed`。自己テスト A-8）。

   **終了コードの読み方**（ここが大事です）。

   | 値 | 意味 | どうする |
   |---|---|---|
   | 0 | 確かめられた | 公開して大丈夫です |
   | 1 | 確かめられなかった（記録なし・つながらない・受け取れたが読めない・空き不足・手元の展開に失敗・もう 1 つ動いている） | 窓の 1 文を読みます。文ごとに何をするかが違います |
   | **2** | **受け取れたが、値か中身が記録と違った** | **公開を止めてください。**配布元のファイルが変わっています |

   1 と 2 を分けているのは、「こちらの都合で分からなかった」と
   「**配布元のファイルが記録と違った**」が全く別の事件だからです。

   **終了コード 1 の中にも、公開を止めるべきものが 1 つあります。**
   「配布元が、このアプリの取りに行かない場所へ案内しました」と出たときです
   （`vd_ng_refused`。`WebFetch.CheckArrivedFrom` が許可ホストの外へのリダイレクトを断ったとき）。
   ファイルは 1 バイトも受け取っていないので 2 ではありませんが、**本番のインストールも同じ理由で必ず失敗します。**
   もう一度押し直しても直りません。配らずに知らせてもらってください。

   オーナーに渡すときは `tools\2_アプリで確かめる.cmd`（ビルドすると exe の隣に入ります）を使います。
   ダブルクリック 1 回で終わります。オーナー向けの手順書（読み方と、何が起きるかの説明）は
   このリポジトリには入っていません。渡すときに `.cmd` と一緒に別に添えます。

   その `.cmd` は、exe が終わったあとに**上の終了コードをそのまま黒い画面に出して `pause` します**
   （`終わりました。結果の番号は 0 です。` の形）。小窓を見のがしても番号だけで判断できますし、
   exe がそもそも起動できなかったときに黒い画面が一瞬で消えることもありません。
   `%errorlevel%` は `chcp` が上書きするので、`.cmd` は `chcp 932` に戻す**前**に控えています。

   > **ゲームが起動するところまで見たいとき**だけ、捨てて構わないフォルダーへ
   > `--action install --game-dir "<そのフォルダー>"` で入れてみてください（窓は出ません）。
   > そのときは先に `%TEMP%\PocketRolesLauncher\BepInEx-Unity.IL2CPP-win-x64-*.zip` を消してください。
   > 残っていると**本物のダウンロードが起きず、その確認は何も証明しません**。
   > （同じ場所に古い `…win-x86-*.zip` も残っているかもしれません。今のアプリはその名前を見に行かないので
   > 邪魔にはなりませんが、もう使わないファイルなので一緒に消して構いません。）

### Claude に頼む場合

このリポジトリで動く自動の作業は、ふだんネットから何もダウンロードしません。
値を取り直す作業を頼むときは、**「BepInEx の zip を公式の配布元から 1 回だけダウンロードしてよい」と、その回ごとにはっきり伝えてください。**

## 3. ゲームの種類（32bit / 64bit）が変わったとき

2026-09-29 に実際に起きたことです。**この文書でいちばん危ない話**なので、別の節にしました。

### 何が起きるか

BepInEx は `winhttp.dll` という名前でゲームに割り込みます。
**Windows は、ゲームと種類（32bit / 64bit）の違う dll を読み込みません。**
そして、そのとき起きるのはこれです。

- エラーは**出ません**
- ログにも**何も出ません**
- ただ **MOD が読み込まれないだけ**です（MOD を入れていないのと同じ画面になります）

ファイルの有無からも見えません。`winhttp.dll` も `BepInEx\core` も、ちゃんとそこに在るからです。
「入れたのに何も起きない」は、たいていこれです。

### どうやって確かめるか

ゲームの exe と `winhttp.dll` の**種類**を見比べます。ゲームは起動しません。

```powershell
function Get-PeArch($p) {
  $fs = [IO.File]::OpenRead($p)
  $b = New-Object byte[] 4
  $fs.Position = 0x3C; $null = $fs.Read($b, 0, 4)
  $fs.Position = [BitConverter]::ToInt32($b, 0) + 4
  $null = $fs.Read($b, 0, 2); $fs.Close()
  switch ([BitConverter]::ToUInt16($b, 0)) { 0x014C { "32bit (x86)" } 0x8664 { "64bit (x64)" } default { "わかりません" } }
}
Get-PeArch "<ゲームのフォルダー>\Among Us.exe"
Get-PeArch "<ゲームのフォルダー>\winhttp.dll"
```

**この 2 つが同じなら大丈夫です。**違ったら MOD は黙って動きません。
アプリの中では `src\Core\PeArch.cs` が同じことをしています。

### どこを直すか

`src\AppInfo.cs` の **3 か所だけ**です。

| 直す物 | 何を書くか |
|---|---|
| `BepZipName` | 新しい種類のファイル名（`…win-x64-…` / `…win-x86-…`） |
| `BepUrls` | **同じ種類の**住所 2 つ（`%2B` の形と `+` の形） |
| `BepZipSha256` | その種類の zip の SHA-256。**版の番号が同じでも、種類が違えば値は別物です** |

`src\Core\Installer.cs` の `BepHref`（固定の住所が 404 になった日に一覧ページから探す「予備の道」）は、
**`AppInfo.BepZipName` のファイル名そのものから自動で組み立てています。**手で直す必要はありませんし、
種類をそこに書いてもいけません。自己テスト「the spare way in follows the pinned version」が、
**版は合っていて種類だけ違うリンクを拾わないこと**を毎回確かめます。

> 版の番号が変わらないまま種類だけ替えるときは、`BepZipSha256` の**同じ鍵に 2 つの値は置けません**。
> 古い種類の値は行としては残せないので、**すぐ上のコメントとして残してください**
> （今の `6.0.0-be.735` がその形になっています）。

### 既に入れてしまった人はどうなるか

**自動で直ります。**`Installer.StepBepInEx`（`src\Core\Installer.cs`）が、[3/5] で
「もう入っているから飛ばす」と決める**前に**、ゲームの exe と `winhttp.dll` の種類を見比べます
（`src\Core\PeArch.cs`）。違っていたら、版が合っていても飛ばさずに入れ直します。

この段がないと、そのフォルダーは「`BepInEx\core` も `winhttp.dll` も在る」状態なので版だけ見て飛ばされ、
**ファイルは全部そろっているのに MOD だけ黙って動かない**という、一番わかりにくい壊れ方になります。

PE として読めないファイルだったときは `PeArch` が「わかりません」を返し、**そのときは入れ直しません**
（読めなかっただけの物を、憶測で上書きしないためです）。

### 記録

| いつ | ゲーム本体 | 入れる BepInEx | `winhttp.dll`（doorstop 4.3.0） |
|---|---|---|---|
| 2026.8.18 まで | 32 ビット | `win-x86` | 22,016 バイト |
| 2026.9.29 から | **64 ビット** | **`win-x64`** | 26,112 バイト |

- BepInEx の**版そのものは `6.0.0-be.735` のまま**です。替えたのは種類だけです。
- Unity の版も **2022.3.44f1 のまま**です（変わっていません）。
- **32 ビットの Windows では、2026.9.29 以降の Among Us 自体が動きません。**

## 4. よくある間違い

| 間違い | どうなるか |
|---|---|
| 版の番号だけ上げて、`BepZipSha256` に行を足さない | ビルドが赤くなります（自己テストが止めます）。そのまま出荷しても、インストールは「記録がありません」で止まります |
| `BepUrls` を古いままにする | 古い zip が落ちてきて、新しい値と合わず、確認で止まります |
| 値を大文字で書く | 自己テストが赤くなります（比べるときは大文字小文字を無視しますが、書き方はそろえます） |
| `x86` や `Unity.Mono` のファイルの値を書く | 確認は通りますが、ゲームが起動しません。しかも**エラーは出ません**（3 章） |
| `BepZipName` だけ種類を替えて `BepUrls` を直し忘れる | 古い種類の zip が落ちてきて、値が合わず確認で止まります（止まるだけまだ安全な方です） |

## 5. どのファイルに何が書いてあるか

| ファイル | 中身 |
|---|---|
| `src\AppInfo.cs` | 版・ファイル名・取りに行く住所・**SHA-256 の表**（`BepSha256()` が引きます） |
| `src\Core\FileHash.cs` | ファイルの SHA-256 を読む・比べる・書き方を確かめる |
| `src\Core\Downloads.cs` | 取りに行ってよいホストの一覧（https のみ、4 つだけ） |
| `src\Core\Installer.cs` | `StepBepInEx`（値が無ければ断る・**ゲームと種類が違えば飛ばさずに入れ直す**）と `CheckAndExpandBep`（確かめる・合わなければ消す・合えばそのまま展開する）、`BepHref`（一覧ページから探す。版も種類も `AppInfo.BepZipName` から） |
| `src\Core\PeArch.cs` | exe / dll が 32bit か 64bit かを PE ヘッダから読む（3 章）。決して例外を投げず、読めなければ「わかりません」 |
| `src\Core\VerifiedZip.cs` | zip を 1 回だけ開いて離さず、値の計算・中身の確認・展開を同じ 1 つの開いたファイルで行う |
| `src\Core\BepVerifier.cs` | `--verify-download`（手順 9）。ゲームのフォルダーを 1 度も名指さずに、受け取る・確かめる・展開する・消すだけを行う |
| `src\Core\Strings.cs` | `in_hash_ok`・`in_hash_bad`・`in_hash_detail`・`in_bep_nohash`・`in_bep_arch`（種類が違うので入れ直す、の 1 文）と `vd_*`（日本語・中文・English） |
| `src\SelfTest\InstallSelfTests.cs` | 「BepInEx: the file itself」と「verify download」 |

`--verify-download` は本番と**同じアドレスの一覧**を見ます。一覧の組み立ては
`Installer.BepAddresses` の 1 か所だけにあり、自己テスト（「verify download」）が
**本番とこのコマンドが同じ順・同じ数のアドレスを試すこと**を毎回確かめます。
別々に書いた一覧は必ずずれるので、そこだけは分けていません。
