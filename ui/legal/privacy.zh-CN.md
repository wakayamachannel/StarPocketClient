## 简要说明

- 我们不会在只是进入房间的人的电脑或手机上安装任何东西，也不会检查任何东西。
- 房主电脑上的记录只存在于该房主的电脑里，不会传到我们这里。
- 房主电脑上的 Aegis 证据记录（有人被移出房间或被限制进入时的记录），所有人的都保留 90 天，因为申诉可能来得较晚（仍然有效的限制的记录可能保留得更久；3.10）。日志等其他记录 30 天后删除。
- PocketRoles 会在那台电脑内，确认已登录的你自己的 Among Us 账号是否在共享限制进入列表上。不会发送任何内容。
- 传到我们这里的，只有你自己发送的东西（咨询、报告 zip、申诉），以及你自己创建的账号的信息。
- 咨询聊天会在最后一次往来的 30 天后删除（申诉进行中的和邮件，最多 90 天）。我们的服务器不保存 IP 地址。
- 咨询机器人是 AI。你写的内容会发送给美国的 Anthropic 公司。工作人员让 AI 写回复草稿时，也只在工作人员按下按钮时，发送给同一家公司。请不要写真实姓名、地址、电话号码、学校、密码。
- 聊天翻译**默认关闭**。开启后，房间里的聊天内容会发送给 Google 或 DeepL。可以在 StarPocket Client 的第一个画面和设置中开启。这是指全新安装；从 v0.5.4 以前升级上来的人，设置文件里仍然是开启（3.9）。
- 在房间里因"确定"等级的作弊被移出的人，会被举报给 Innersloth（**默认关闭**）。可以在 StarPocket Client 的第一个画面和设置中开启。无论用哪种方式安装，都从关闭开始（3.9）。
- StarPocket 账号可以不创建。即使创建了，也不会与游戏中的你关联。
- 想删除记录时，在房间聊天中输入 `/cmd id`，把显示出来的代码发给我们。
- 未满 18 岁的人，请和家长一起阅读。

### 3.3 报告 zip 和单人证据 zip

1. 按启动器或 Client 的"制作报告 zip"，会在房主电脑的桌面上生成 zip。**不会自动发送。** 是否发送由你决定。
2. 内容
   - 游戏日志、启动器记录、电脑和游戏的版本
 - 最近 90 天的 Aegis 证据记录（按从新到旧最多 200 条、5 MB；更早的记录用第 5 项的"单人证据"zip 发送），以及超过 30 天的记录所附的、支持该记录的 2 行游戏日志（代替已删除的日志）（3.10）
3. 不放入的、会遮盖的
   - 不放入：API 密钥、Discord Webhook、设置文件、密码
   - 遮盖：PUID、好友编号、哈希值的开头、删除记录用的代码（日志中的）、含有 Windows 用户名的地方
   - 证据记录中有该玩家的名字、PUID 的哈希值、删除记录用的代码（不放好友编号及其哈希值）。
   - 不遮盖代码，是为了让作者处理删除记录的请求：与删除列表中的代码核对，把作者和管理员手中该玩家的记录也删除（3.5）。
4. zip 里也有当时在房间里的其他人的名字，以及证据记录中的人的代码。请不要贴在公开的地方，请用邮件发送。
5. **单人证据 zip**（用于申诉）：房主在启动器的"单人证据"（Client 中为报告的地方）输入某个人的"删除记录用的代码"、好友编号或证据编号（AEG-…）中的任意一个，就会在桌面上生成只含这个人记录的小 zip。这是作者调查申诉时请房主制作、由房主用邮件发给作者的文件。**不会自动发送。** 房主即使没有被请求，也可以随时为这台电脑上有记录的任何人生成（其中的内容本来就保存在这台电脑上）。交给作者以外的人，是游玩规则 第7条所禁止的。你提出申诉时，作者会收到那位房主电脑上你的全部记录（不只是你申诉的那次限制，也包括仅被移出房间的记录）。
   - 内容：这个人留在房主电脑上的证据记录（超过 90 天的记录，只放入仍然有效的限制的证据）、支持这些记录的游戏日志行，以及电脑和游戏的版本（与报告 zip 相同的 `system.txt` 等，用于让限制进入的管理应用分辨来自同一台电脑的 zip）。被要求删除的记录（已经清空的，以及在删除列表上的）不放入。
   - 不放入其他人的记录和日志（这个人的记录的检测文字中，有时会出现同一局其他人的名字）。
   - 用来确定是哪些记录的，是记录中的"删除记录用的代码"：作者会与提出申诉的人用 `/cmd id` 看到的代码进行比较。**这个代码不能证明发来的人就是本人**（第12条第5项：它不是密码；在未注册的房间里所有人都能看到，而且它也在房主的记录和报告 zip 中，所以其他人也可能知道）。因此，仅凭代码一致，作者不会告知记录的内容（理由、时间、房间代码、其他人的名字）。需要进一步确认时，使用第12条第2项的追加问题（这些问题的答案正是这个 zip 里的内容，所以当 zip 落到本人以外的人手里时，答案一致也不作为本人的证明）。不放入好友编号，也不放入它的哈希值；房主用好友编号查找时也一样（好友编号的哈希值可以通过逐一尝试还原，放入也起不到保护作用）。
   - 遮盖方式与报告 zip 相同。和报告 zip 一样，30 天后启动器会自动删除。
   - 这个 zip 请只发给作者（游玩规则 第7条第1项）。其中包含此人的"删除记录用的代码"，以及入室限制列表使用的 PUID 哈希值。

### 3.5 限制进入的管理应用（作者和管理员的电脑）

1. 发来的报告 zip 和单人证据 zip（3.3）中的证据记录，会导入作者和管理员电脑上的限制进入的管理应用。
   - 导入的证据记录中有该玩家的名字、PUID 的哈希值、删除记录用的代码（3.3）。因此作者和管理员也会收到发送 zip 的人以外的其他人的代码。
   - 代码用于与删除列表核对，以删除请求删除者的记录（目前的限制进入的管理应用还没有核对；见第 4 项的）。
2. 操作记录（`audit.log`）中会留下：
   - 时间、操作、证据编号、名字、规则、理由、提议人
   - 不保留好友编号和 PUID。
3. 使用目的：正确地、事后可核查地决定共享限制进入和申诉。
   - 仅以其他房主发来的记录设定共享限制进入时，按以下规定（游戏规则 第9条第2项）：
     - "确定"等级的检测，且记录与该房主的游戏日志一致时：1 位房主的记录即可，但只限第一个等级（最多 30 天）；仅凭同一位房主的记录决定的，30 天最多 2 件
     - 其他情况（"重复"等级的检测、聊天、伤人的话、骚扰、由房主看了之后决定的限制）：在 30 天内收到的 2 位以上不同房主的记录，或值得信赖的管理员的报告；或者作者写下理由并保存在 `audit.log` 中
     - 这里的 3 个数字计算的东西各不相同。**人数**：2 位以上不同房主（今后房主变多时可能会提高）。**件数**：仅凭同一位房主决定的，30 天最多 2 件。**次数**：下一行的"30 天内有 3 次被确认有误"。
     - 举报在 30 天内有 3 次在申诉中被确认有误的房主，将不再受理其举报（"确定"等级的检测出错不计算在内。游戏规则 第7条第3项；使用条款 第13条；S-11）
   - 为此，作者以"有误"为由解除共享限制进入时，会留下发送原举报的房主的记录（来源房主的记录 `reporters.txt`，以及操作记录 `audit.log` 中的行）。内容是房主的名字（作者导入报告 zip 时起的名字）、电脑标识（由 zip 中的文件生成的简短标记，用于分辨从同一台电脑发送的 zip）、日期、证据编号，以及是哪一次解除。只用于计算次数。`reporters.txt` 中的行在 30 天后删除。`audit.log` 中的行与第 4 项的操作记录相同处理。
4. 目前导入的记录和操作记录没有期限，也没有使用删除列表。公开前会改为：
 - 在事件结束 90 天后删除
   - 删除删除列表中的代码所对应的记录
   - 让操作记录中的名字可以被遮盖

### 3.11 Aegis 的扫描

1. Aegis 只检查房主电脑中的以下内容：
   - Among Us 和 MOD 文件夹中文件的名称和内容（哈希值）
   - 正在运行的应用的**名称**和**程序文件**（v0.5.5 起）
     - 为了找出改名的作弊，也会检查程序文件（.exe）。检查的是：由内容生成的标记（SHA-256）、文件里写的产品信息、签名者的名字。这些只在本机与可用于作弊的工具名单比较。
     - 是不是 Microsoft 的，按证书能否追溯到 Microsoft 的根证书判断，而不是看签名者的名字。
     - 程序文件的位置只向 Windows 询问。不查看应用的内存、窗口或画面。
     - 只检查与你同一个 Windows 会话的应用（不查看 Windows 的服务，也不查看其他用户的应用）。
     - 结果不会发送到任何地方。
   - 已加载的驱动程序的名称
   - Windows 的保护设置（安全启动、TPM、测试模式等）
   - 在游戏中（PocketRoles 的自检），还会检查加载到游戏中的 DLL 的名称、位置和签名（与作弊名称比较；从 Windows 文件夹加载的也会比较名称），以及游戏代码（内存中的 GameAssembly.dll）是否被改写。只检查游戏自身内部。
   - 游戏中的 PocketRoles（计划）会把已登录的 Among Us 账号的 PUID 和好友编号，转换成与共享限制进入列表相同形式的哈希值，与列表比较。PUID 和好友编号只在内存中使用，不会写下来，也不会发送。
   - 游戏中的 PocketRoles、托盘中的 Aegis、现在的启动器和 StarPocket Client（计划），会从 Windows 的设置（注册表）读取当前登录 Steam 的账号编号，转换成 3.10 中的简短标记和打开内容用的密钥，只用于分辨 `access-status.txt` 中的哪一行。这是为了在与家人共用的电脑上，不在画面上显示其他人的限制进入和代码。编号本身不会写下来，也不会发送。
2. 不查看照片、文档、其他应用的画面、键盘输入、浏览器、密码。
3. 电脑扫描的结果不会发送到任何地方。
   - 即使在"现在无法开始游戏"画面上按"联系我们"，预先填入的也只有代码、应用版本和语言。不会填入发现的东西的名称（想写的话，由你自己写）。
   - 在房间里发现"确定"等级的作弊并把人移出房间后向 Innersloth 举报的功能（3.9），是对房间内情况的判定，不是电脑扫描的结果。
   - 共享限制进入自我确认的结果，也不会发送到任何地方（3.9）。
4. 扫描的时机
   - 现在的启动器：打开时；托盘中的 Aegis 运行期间每 30 秒（应用名称和程序文件；新启动的应用每 2 秒察觉；发现时只会通知并写入 `events.log`，不会阻止）；按下开始游戏时
   - StarPocket Client（计划）：打开时、游戏文件变化时、定义文件更新时、窗口可见期间每 30 秒（应用名称和程序文件）、按下"重新检查"时、按下开始游戏时
   - PocketRoles（游戏内）：启动时、每 60 秒、打开菜单时（只在游戏自身内部）
   - 自己账号的确认（PocketRoles，计划）：登录期间，每 2 秒查看账号是否变化。在账号变化、定义文件更新、到期时，以及创建房间前，重新比较
5. Aegis 不安装驱动程序，不重启电脑，也不更改设置。

   2. 关于 Aegis：检查什么、不做什么（不安装驱动、不重启、不发送电脑扫描的结果）、"安装"
   3. 安装：进度，以及现在在做什么的一行说明

   - 如果使用目的的变更大到无法说与原目的有关联，会在使用前取得本人的同意（日本《个人信息保护法》第17条、第18条）。
   - 依靠同意发送到国外时，每增加一个新的发送对象，都会取得同意（第28条）。
   - 对没有同意的人，不会开始新的发送，也不会用于新的目的。
4. 改错字等不改变意思的修正，只登在修改记录中。
5. 本政策的正确文本，只有官方网站、官方 GitHub 仓库、官方（由我们签名的）StarPocket Client 中的文本。
